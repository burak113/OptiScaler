# Exact proposed integration contract (default off, research only)

This is an **adapter specification**, not an applied production patch. Job08
must first accept the actual candidate revision and local GPU results. No frozen
production header, shader, default or generated bytecode changes in this job.
`SupportCertifiedApply.hlsl` is uncompiled source: there is no claimed CSO, GPU
parity, performance result, native RR result or visual improvement.

## Scope and ownership

The baseline shared `FSRDPostMotionAnchorApply.hlsl` receives only `InGain` and
private D/S UAVs; it cannot determine pixel eligibility or certify gain donors.
Replacing its bilinear sample with a depth lookup is insufficient. The native
gain at a cell uses a 3x3 footprint with default spacing **three cells** (24
render pixels), and each native Stats cell uses four bilinear taps, covering 16
selected source pixels. Certify the entire actual nonzero donor and recalled-key
footprint. The CPU candidate deliberately uses all 64 current pixels for a more
conservative C8 certificate; this includes thin surfaces absent from sparse taps.

Job02 owns gain estimation; job01 owns numerical formats and sampler parity;
job08 owns host ABI, source selection, lifecycle and publication. The support
builder and interfaces in `reconstruction.py` are the executable specification.
The current native capture has neither the required certificate nor raw keys.
Until those are supplied, this shader MUST NOT be enabled for real native input.

## Resources and ABI

| Binding | Resource | Required contents |
| --- | --- | --- |
| t0 | `Gain`, R32_FLOAT | Bounded scalar gain in [0,1]; an explicit conversion from existing RGBA16F is allowed only with recorded rounding. |
| t1 | `CellPointDepth`, RGBA32_FLOAT | XYZ representative point, W positive absolute view-depth scale. |
| t2 | `CellNormalValid`, RGBA32_FLOAT | XYZ unit normal in the same basis; W=1 only if **every nonzero estimator donor and temporal key support** is certified. |
| t3 | `QueryPositionDepth`, RGBA32_FLOAT | Current point in the same basis, W original signed linear view depth. |
| t4 | `QueryNormalEligibility`, RGBA32_FLOAT | XYZ original geometric normal, W=1 only for observed, valid, eligible current pixel. Never derive this from corrected colour/gain. |
| u0/u1 | Native private D/S, RGBA16_FLOAT | Exact active extent; preserve each source alpha/hit-distance channel. G3 continues using original inputs. |
| u2 | `SupportDebug`, RGBA32_FLOAT | Gain, original accepted interpolation mass, contributor count, query eligibility; a partial mass is not full temporal validity. |

`SupportConstants` is exactly 48 bytes (three 16-byte registers): offsets 0/8
`uint2 ActiveExtent/GridExtent`; offsets 16/20 `uint Cell/Enabled`; offsets 24/28
`float PlaneAbsolute/PlaneRelative`; offsets 32/36 `float NormalCosine/MinimumWeight`;
offset 40 `uint2 Reserved={0,0}`. Defaults are C8, disabled, 1e-5, 1e-4,
cos(3 degrees), 1e-8. All thresholds must be finite. Use HLSL `Load` and explicit
four-tap arithmetic; do not introduce a CLAMP sampler or use allocation UVs.
Grid extent is ceil(active/Cell); incomplete edge cells are invalid. The shader
checks dispatch active bounds; the host must validate every bound resource's
extent before recording. Max-size allocation does not change active coordinates.

The CPU oracle normalizes the query normal in float64. HLSL normalizes in FP32;
GPU agreement near hard boundaries must therefore report acceptance differences,
not merely output average error. The provided shader intentionally skips identity
writes and multiplies finite native radiance without adding new sanitization.
Malformed source radiance remains an upstream numerical/validation issue. D3D
FP16 store behavior must be measured against job01's accepted numerical contract.
CPU `apply_rgba` copies alpha bits, including adversarial payloads, directly.
The HLSL typed FP16 load/store carries alpha as a float value; it does **not**
prove preservation of arbitrary NaN payload, subnormal or signed-zero bits on
changed pixels. Request raw-word alpha equality for the actual legal native
hit-distance domain. OFF and unsupported paths skip the store entirely.

## Host insertion points and lifetime

1. Add a separate default-off diagnostic route beside native
   `FSRDNrdPostMotionAnchor_Dx12.h::Prepare/Describe/RecordOwned`; preserve the
   untouched baseline route. Existing native pass2 has three descriptors and
   its slot heap has 18 entries. The new Apply has eight descriptors, so a
   separate diagnostic layout needs at least 23 entries before support-build
   resources/passes. Never append bindings without updating the root signature,
   descriptor ranges, heap capacity, upload layout and tests together.
2. Obtain **original** depth/motion/normals from the precise native input stage;
   the current anchor input structure has no normal binding. Extend only the
   diagnostic adapter with explicitly sourced normals. Surface MVs, expected
   camera motion, original depth and history support determine eligibility.
   Input alpha is not assumed to be a usable virtual reflection-distance witness.
3. Produce current per-cell plane/cone support and independent per-pixel
   eligibility. Job02 must report its actual nonzero estimator donors and valid
   recalled samples; aggregate those as `certify_estimator_support` requires.
   Unavailable source/camera/history data yields W=0 and identity, not a guessed
   certificate. A two-pass GPU certificate builder is pending implementation and
   measurement by the integrating workstream; the CPU builder is runnable now.
4. Dispatch support generation after required original guides are visible and
   before Apply; use correct SRV/UAV transitions and UAV barriers. Retain every
   referenced resource, CB allocation and descriptor through the submitted fence.
   Publish a camera/key pair only after a proved GPU write and ordering contract.
   Discard/reset invalidates logical keys but does not release inflight physical
   storage. See `history.py` and the ledger for the conservative publication model.
5. Keep original native G3 inputs separate from owned private D/S consumed by
   RR/NZR. Preserve D16/S256, G2/G3, RR Fallback, Diffuse RR, Reflection History,
   and NZR Temporal OFF. Do not install or replace the user's DLL.

## Separate coordinate experiment

The source-derived +0.5 pixel and odd-grid normalized-stretch witnesses are
independent of reconstruction. Do not apply a half-pixel change while scoring a
gain-estimator change. First run identity/translation/jitter witnesses using the
actual native/combined matrix upload and sampler; only then propose a separately
scoped Stats change. Native keys store abs(depth); combined signed-key behavior
must retain its own label. This candidate makes no speculative production fix.

SHA. No generated CSO/header is included here. Frozen native Stats/Gain use

Use `GPU_REQUEST.json` for phase textures, centre-versus-pixel counterexample,

CPU arithmetic operation counts or runtime are not GPU performance. The proposed
FP32 debug guides are deliberately explicit and can be expensive; profile and
pack only after correctness. No allocation or <=1ms claim is made. Even a fully
valid geometry certificate cannot distinguish coplanar radiance/material changes
or surfaces separated below guide precision/tolerance. Keep as research.
