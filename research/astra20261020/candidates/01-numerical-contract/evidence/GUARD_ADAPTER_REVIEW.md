# Independent engineering review of the finite depth guard proposal

Reviewed by the sampling/coordinate implementation agent. This review is
independent of the coordinator's adapter implementation; the task's separately
blinded skeptical reviewer also reviews the proposal. Files reviewed read-only:
`numerical_contract/guards.py`, `gpu_inputs.py`, and the frozen
`FSRDColourTrackTrack.hlsl` / its host resource declarations.

## Proposed change and falsifier

Keep the existing outer history-enabled, viewport and nonzero history-depth
conditions. Change only the final depth predicate from

```hlsl
abs(history.a - expected) <= Params.y * max(abs(expected), 1e-3f)
```

to

```hlsl
isfinite(expected) && isfinite(history.a) &&
abs(history.a - expected) <= Params.y * max(abs(expected), 1e-3f)
```

where `expected = centre.a + motion.z`.

**Prediction:** when finite, nonzero sampled history depth is compared with
infinite expected depth, the original float32 expression can accept because
both sides become positive infinity. The proposal rejects it. For finite
sampled depth and finite computed expected depth, every original accepted or
rejected result must remain identical, including signed depths and the
inclusive tolerance boundary. A changed decision in that finite domain
falsifies the preservation claim.

**Important representation boundary:** production Colour Stats and Motion are
`R16G16B16A16_FLOAT` resources. Two finite FP16-expanded values cannot overflow a
float32 addition; their maximum same-sign sum is 131008. Consequently,
`F32_MAX + F32_MAX -> Inf` is a useful arithmetic test, but is not claimed to be
reachable from two finite current production R16 values. An attainable typed
resource witness instead stores an FP16 `+Inf` or `-Inf` in `centre.a` or
`motion.z`, and finite nonzero history depth. That distinction must remain in
the GPU request and final report.

## Scope and recommendation

The proposal repairs a numerical validity hole. It does not change denoising
policy, tolerances, EMA weights, sampling, packing, lobe units, alpha, current
source authority or the default-off setting. There is no reason to enable
ColourTrack based on this correction alone. The only affected production
source line belongs in `adapter/PRODUCTION.patch` for integration job 08; the
tagged source and generated shader artifacts remain frozen in this job.

The extra sampled-history `isfinite` check is explicit defensive validity. With
the host's finite positive 0.02 tolerance, an infinite history and finite
expected depth already reject; the actual demonstrated hole is finite history
versus infinite expected depth. Including both checks expresses the supported
finite depth domain without changing finite cases.

This review supports a **default-off numerical A/B proposal pending local
compilation and GPU parity**, not a visual-quality acceptance. Explicit HLSL
`isfinite` checks still need to survive the actual compiler flags/optimization
and GPU execution. CPU NumPy comparisons are not proof of DXC behavior on
nonfinite values. Record compiler and bytecode hashes after actual local build;
existing generated bytes do not implement the new predicate.

## GPU microcase review

The current `gpu_inputs.py` phase sweep is well separated from storage: its two
depth texels (1 and 1.0625) are exactly representable in FP16; the same UV array
feeds ideal/source/observed profiles. Its source/observed results are model
predictions. The native sum microcases use physical lobe constants whose
current/recalled totals exceed the low 32-bit word; their reset and returned
byte layout are explicit. Neither case alone validates the proposed new guard.

The guard request must add at least these exact typed inputs:

| Case | `centre.a` FP16 bits | `motion.z` FP16 bits | `history.a` FP16 bits | Expected old / guarded CPU predicate |
|---|---|---|---|---|
| Positive infinite expected | `0x7c00` | `0x0000` | `0x3c00` | true / false |
| Negative infinite expected | `0xfc00` | `0x0000` | `0xbc00` | true / false |
| Infinite motion | `0x3c00` | `0x7c00` | `0x3c00` | true / false |
| Both finite and matching | `0x3c00` | `0x0000` | `0x3c00` | true / true |
| Finite mismatch | `0x3c00` | `0x0000` | `0x4000` | false / false |
| NaN expected | `0x7e00` | `0x0000` | `0x3c00` | false / false |

Use zero XY motion, `Params.w=1`, `Params.y=float32(0.02)`, a 1x1 quarter
texture, and UV `(0.5,0.5)`. `InStats`, `InMotion`, and `InPrev` match the
production R16G16B16A16_FLOAT declarations. Upload the exact half payloads;
avoid generating infinities through a compiler-folded literal expression.
Export the loaded depth bits, expected float32 bits, old predicate and guarded
predicate to a diagnostic uint UAV before any EMA/gain output can hide the
branch. Also run history-disabled with poisoned unused history/motion inputs.

A separate R32 structured-buffer arithmetic case may use finite
`0x7f7fffff + 0x7f7fffff` to test overflow, explicitly labeled outside the
production all-finite R16 input domain. The negative mutant is removal of the
new finite check; it must reproduce the old accepted invalid history. A mutant
changing `<=` to `<` must fail the preserved inclusive-boundary check.

Apply the same resource transitions, UAV barrier, readback fence, descriptor
validation and source/compiler provenance rules as the primary GPU request.
No GPU run has been performed by this reviewer.

## CPU review tests

Executed after the coordinator added the separate
`guards.colour_history_valid_finite` implementation. From the candidate folder:

```sh
python -B -m unittest discover -s tests -p 'test_guard_adapter.py' -v
```

**9 tests passed in 0.077 s, exit 0**, Python 3.12.14 / NumPy 2.3.5. Executor:
sampling/coordinate implementation agent. The coordinator's final combined run
supersedes this preliminary owned-suite timing.

- All 63,488 finite FP16 payloads were tested against each of four predetermined
  motion probes (`0`, `2^-10`, `-2^-10`, `65504`): **253,952 comparisons and zero
  changed decisions**. Every expected-depth float32 sum was finite.
- **4,096** additional finite current/motion/history cases, seed `2026102031`,
  also gave **zero changed decisions**. History values include float32
  interpolation between half endpoints, rather than assuming every sampled
  result is itself representable in FP16. The UV population includes values
  outside the valid viewport.
- All three specified typed-infinite expected-depth cases reproduced source
  acceptance and proposed rejection. Finite controls and NaN controls retained
  their expected results.
- For the actual host tolerance `float32(.02)`, expected depth 50 and sampled
  depth 51 make both sides exactly 1. The signed negative equivalent also
  passes. A `<` mutant fails both boundary cases. Neighboring float32 values
  test either side without changing the tolerance.
- Inactive history never converts poisoned unused history, motion or UV
  objects. Current-source authority still returns the original RGBA bit pattern
  without inspecting an unused gain object.
- The finite-F32 overflow intervention reproduces old acceptance and guarded
  rejection in float32. Float64 removes the overflow and rejects naturally;
  that result is explicitly an analytic arithmetic intervention.
- The GPU-input generator emits ordinary JSON, consistent input sample counts,
  exact high/low reconstructed sums, and all 32 expected reset bytes. This
  validates generated CPU requests, not a GPU execution.

At this review's execution, `gpu_inputs.py` had not yet added guard-specific
arrays. The coordinator has the exact required typed cases above; their
inclusion and the final patch/build instructions remain part of the combined
delivery review. No adapter patch file or generated bytecode was executed by
this reviewer.
