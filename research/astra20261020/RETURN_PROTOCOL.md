# Required return bundle

Place the task result inside its candidate directory. Include:

1. `REPORT.md`: mechanism, competing hypotheses, distinct predictions, data
   selection, baseline calibration, held-out results, negative controls,
   limitations, independent review and your recommendation.
2. `RESULT.json`: task id; base tag and resolved commit; source revision; changed
   paths; dependency versions; seeds; exact CPU commands, exit codes and elapsed
   times; fixture and result hashes; measured comparisons; rejected hypotheses;
   unresolved risks; `gpu_executed:false`; acceptance status. Use `null` for
   unavailable measurements. Attribute results to their actual executor.
3. `tests/` and runnable sources; lock the test data and disclose generated data.
   Include one explicit command that runs the meaningful task checks.
4. Candidate HLSL plus a scoped adapter patch if a shader/host change is proposed.
   Record compiler profile, entry point and flags. Label generated bytecode as
   pending local compilation unless actually built and verified.
5. `GPU_REQUEST.json`: exact pass, input roles and formats, capture/frame ranges,
   dimensions/stride/crop, constants, output resources, baseline/candidate pairs,
   startup/reset/order, D3D debug/lifetime checks, tolerance with rationale,
   timings/memory scope, and visual failure criteria. Unknown fields must be
   explicit, not guessed. Ask for the smallest experiment that distinguishes the
   remaining hypotheses.

If blocked by data, add `BLOCKED_DATA_REQUEST.json` with each missing observable,
why the current data cannot identify it, exact capture stage/format/extent/frame
sequence, proposed local extraction, maximum useful payload, and the competing
outcomes. Raw ring keys, original native pre-store atomic sums and converged
same-pose ground truth are not magically present in this package.

Use ordinary JSON numbers, not NaN/Infinity. Include hashes of relevant files
but exclude MANIFEST self-hashes. Don't rewrite a failed test as a successful
measurement. A report should distinguish observed data, modeled behavior and
hypotheses sentence by sentence.

For a PR, target `sol/26-integration`, include commands and limitations in the
description, and return its URL and head SHA. Do not merge it. For a ZIP, include
`git diff --binary <base>...<task-head>` (or an equivalent patch including new
files), source files, result files, SHA256 manifest and application instructions.
Verify the patch on a clean checkout of the recorded base. Exclude credentials,
machine-specific absolute paths, DLLs, build caches and unrelated repository
history. A broken export is not a completed task.
